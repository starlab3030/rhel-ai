## 1. 개요

**vLLM (Virtual Large Language Model)**
* [vLLM 커뮤니티](https://github.com/vllm-project)에 의해 유지 관리되는 오픈소스 코드 라이브러리
* 대규모 언어 모델(Large Language Model, LLM)이 계산을 더욱 효율적이고 대규모로 수행할 수 있도록 지원
* 구체적으로는, GPU 메모리를 더욱 효율적으로 활용하여 생성형 AI 애플리케이션의 출력을 가속화하는 추론 서버
<br>
<br>

## 2. vLLM의 작동 방식

### 2.1 추론 서버란

**추론이란**
* 근거를 기반으로 결론을 내리는 것
  + 예) 친구네 집 거실에 불이 켜져 있지만 친구는 보이지 않는 경우, 입증할 만한 확실한 근거는 없어도 친구가 집에 있다고 추론 가능
* 일종의 소프트웨어인 언어 모델 역시 단어나 문구의 의미에 대한 확실한 근거가 없기 때문에 학습한 내용을 근거로 활용
  + 언어 모델은 데이터를 기반으로 한 일련의 계산을 통해 결론을 생성
  + 예) 불이 꺼져 있으면 친구가 집에 없다고 추론

**추론 서버**
* AI 모델이 이전 학습 내용을 바탕으로 새로운 결론을 내리도록 돕는 소프트웨어
* 머신러닝 모델을 통해 입력 요청을 제공하며 출력을 반환
<br>

### 2.2 수학을 통해 결론을 도출하는 LLM

**LLM의 추론**
* LLM은 학습 과정에서 수학적 계산을 통해 학습
* LLM은 일련의 확률 계산(수학)을 수행하여 답변(추론)을 생성
  + LLM이 사람의 요청을 이해할 수 있으려면 각 단어가 서로 관련된 방식과 단어 간에 연관을 짓는 방법을 이해 필요
  + 사람처럼 의미를 학습하고 단어를 사용하여 추론하는 대신, LLM은 수학을 사용하여 추론
* LLM은 매일 수백만(??) 명의 사용자에게 답변하면서 대량의 계산을 수행
  + 애플리케이션이 실행 중인 동안 이 모든 계산을 한 번에 처리하는 것은 부담
  + (전통적으로) LLM 실행에 필요한 처리 능력이 상당량의 메모리를 빠르게 소모할 수 있기 때문

> [!NOTE]
> vLLM 아키텍처를 업그레이드하면 메모리, 속도 등과 같은 요소의 리소스 효율성이 지속적으로 개선됩니다.
<br>
<br>

## 3. vLLM과 PagedAttention

### 3.1 LLM 메모리 관련 연구 논문

코넬 대학의 [PagedAttention을 사용한 대규모 언어 모델의 효율적인 메모리 관리](https://arxiv.org/abs/2309.06180)의 연구에서 기존 LLM 메모리 관리 시스템이 다소 비효율적인 방식으로 계산을 체계화한다고 지적되었습니다. 

> [!NOTE]
> **PagedAttention**은 운영 체제 내의 페이징 시스템과 가상 메모리에서 영감을 얻은 vLLM을 통해 도입된 메모리 관리 기법입니다.

이 연구는 키-값(KV: Key & Value) 캐시(LLM의 단기 메모리)가 처리 중에 어떻게 감소하고 증가하는지 확인하고, 더욱 안정적인 방식으로 공간과 컴퓨팅 성능을 관리하기 위한 솔루션으로 vLLM을 제시합니다.

> [!NOTE]
> 기본적으로, vLLM은 사용자 응답을 연속적으로 '배치 처리'하여 KV 캐시가 바로가기(shortcut)를 만들도록 안내하는 일련의 지침입니다.
<br>

### 3.2 KV 캐시

**KV (Key & Value)**
* 키값(KV)은 LLM이 단어 또는 문구의 의미를 형성하는 방식
* 예) 메뉴판 품목의 키값(KV)을 처리하는 경우
  + 프렌치프라이(키)의 가격은 16,000원(값)로 책정되어 있음
  + 계산원이 프렌치프라이 주문을 등록하면 해당 '키'의 계산된 '값'은 16,000원
* LLM은 각 키(또는 토큰)에 해당하는 값을 캐시에 저장한다는 점에서 이와 유사하게 키 값을 처리

**KV 캐시**
* KV를 위한 단기 메모리 스토리지
* KV에 대한 읽기 & 쓰기의 성능을 위해 사용
<br>

### 3.3 연속적 배치 처리

**연속적 배치 처리**
* 전반적인 처리 효율을 개선하기 위해 여러 쿼리를 동시에 처리하는 데 사용되는 기법
* 예) 챗봇이 분당 수천 개의 쿼리를 수신하고 있는데, 그 쿼리 중 대부분이 "한국의 수도가 어디야?", "미국의 수도가 어디야?"처럼 비슷한 경우
  + 두 쿼리는 공통적으로 '수도가 어디야'라는 부분을 포함
  + 이 부분은 LLM이 의미를 얻기 위해 수많은 계산을 해야 하는 토큰(단어) 문자열
  + vLLM을 사용하면 챗봇은 이 토큰 문자열('수도가 어디야')을 단기 메모리(KV 캐시)에 저장하고 번역 요청을 두 개 대신 하나만 보낼 수 있음

**vLLM의 연속적 배치 처리**
* vLLM 방식
  + vLLM은 새로운 응답을 생성하는 대신 KV 캐시에 메모리를 저장
  + 이전에 수행한 계산과 유사한 새 쿼리에 대한 바로가기를 생성
* 위와 같이 vLLM은 유사한 쿼리의 계산을 개별적으로 처리하는 대신 배치 처리하면 처리량을 개선하고 메모리 할당을 최적화
  + vLLM은 대규모 배치 크기와 컨텍스트가 긴 텍스트의 토큰 용량을 확장하고 메모리를 최적화  
<br>
<br>

## 4. 조직에서 `vLLM`을 활용할 수 있는 방법

### 4.1 배경

일반적으로 LLM 기반 애플리케이션은 필요로 하는 하드웨어 요구 사항에 의해 매우 높은 가격이 책정됩니다. 이런 상황에서 조직이 `vLLM`을 사용하면 ***'더 적은 비용으로 더 많은 효과'***를 누릴 수 있습니다.

비용 효율적이고 신뢰할 수 있는 LLM 서비스를 구축하려면 상당한 수준의 컴퓨팅 성능, 에너지 리소스, 전문적인 운영 기술이 필요합니다. 이러한 문제로 인해 많은 조직이 사용자 정의되고 즉시 배포 가능하며 보안이 강화된 AI가 제공하는 이점을 누리지 못하고 있습니다.

`vLLM`과 그 기반이 되는 알고리즘인 *PagedAttention*은 AI 워크로드를 지원하는 데 필요한 하드웨어를 더욱 효율적으로 활용하여 이러한 문제를 해결하는 것을 목표로 합니다.
<br>

**`vLLM`을 LLM의 추론 서버로 사용 시 이점**

## 5. vLLM이 LLM 성능 향상의 표준으로 자리 잡고 있는 이유

### 5.1 vLLM이 제공하는 최적화 기능

*PagedAttention*은 vLLM에서 파생된 주요 알고리즘이며, 이 외에도 다양한 기능을 제공
* PyTorch 컴파일/CUDA 그래프로 GPU 메모리 최적화
* 양자화(Quantization)로 모델 실행에 필요한 메모리 공간 절약
* 텐서 병렬 처리로 여러 GPU에 처리 작업 분할
* 추측 디코딩(Speculative Decoding)으로 작은 모델을 사용하여 토큰을 예측하고 더 방대한 모델을 사용하여 해당 예측을 검증하는 방식으로 텍스트 생성 속도 향상
* 플래시 어텐션(Flash Attention)으로 트랜스포머 모델의 효율성 개선
<br>

### 5.2 vLLM의 유연성 및 효율적인 미세-조정(fine-tuning) 기술

**유연성**
* vLLM의 인기가 높아지는 데는 최적화 기능 외에 유연성도 한 몫을 제공
* vLLM은 소규모 언어 모델과 대규모 언어 모델 모두에서 원활하게 작동하고 널리 사용되는 모델 및 프레임워크와 통합 가능
* vLLM은 오픈소스 특성을 기반으로 코드의 투명성, 사용자 정의, 더욱 빠른 버그 수정을 지원

**효율적인 미세-조정**
* LoRA와 QLoRA는 사용자가 비용과 컴퓨팅 리소스를 최적화하는 데 도움이 되는 리소스 효율적인 미세 조정(fine-tuning) 기술을 제공
<br>
